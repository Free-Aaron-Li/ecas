# ECAS 实现设计 — Edge-Cloud Acquisition System

> 本文档定义 **代码级规范**。架构决策请见《全局设计》，本文不重复。
> 核心目标： **全体代码完全符合 RAII**； **拒绝裸露异常跨越模块边界**； **错误、警告、日志一律向上管理**； **最大化运用 C++26
协程、静态反射、契约等现代化特性，拒绝任何过时特性与宏黑魔法**。
> 文档家族：`全局设计.md`（架构）+ `全局设计.md`（本文，代码）

---

## 0. 总纲：六条不可推翻的铁律

| # | 铁律                                 | 一句话解释                                                                                                                                                     |
|---|--------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | **RAII 全生命周期**                  | 任何资源自诞生即被析构语义确定的对象拥有；析构 `noexcept`；禁止裸 `new`/`delete`、裸句柄作为拥有者                                                             |
| 2 | **拒绝裸露异常跨越模块边界**         | 模块对外接口**不抛异常**；失败以 `std::expected<T, Error>`（或 `Result<T>`）返回；异常仅限内部实现细节                                                         |
| 3 | **错误 / 警告 / 日志向上管理**       | 错误必须**携带上下文**逐层上送，不允许中途吞没；日志由**调用方**决定如何记录；底层只负责"产生结构化错误"                                                       |
| 4 | **C++26 现代化，拒绝过时与宏黑魔法** | 使用 Modules、Concepts、coroutines、`std::expected`、`std::generator`、`std::execution`、静态反射、契约；**禁止 C 遗留、宏技巧、`#define` 封装、手动资源管理** |
| 5 | **协程即异步范式**                   | 所有异步 / 流式 / 延迟计算优先用协程（`std::generator`、`task`）表达；禁止回调地狱、手动状态机                                                                 |
| 6 | **契约即接口的一部分**               | 所有对外接口用前置条件、后置条件、不变量声明约束；优先 C++26 契约，不可用时代码等价降级                                                                        |

> 性能、便利性、开发速度 **均不得违反上述六条**。评审以这六条为第一检查项。

## 1. 语言与编译

### 1.1 C++26 特性使用规范（最大化采用）

ECAS 以 **C++26** 为基线，编译器策略为 **GCC 16.2+（首选）、Clang 24+（备选对标）、MSVC（暂不考虑）**（见《全局设计》§3.2）。因协程、静态反射、
`std::execution`、契约等特性在支持度上仍有差异，采用"**可用即用、演进有路**"原则——下表按 **标准化状态**分层，避免把未落地特性写成既成事实，也
**不因部分编译器滞后而全体退化**。

#### 1.1.1 已标准化的核心特性（ **默认全量使用**）

| 特性                                           | 标准      | 用途                           | 规则                                                         |
|------------------------------------------------|-----------|--------------------------------|--------------------------------------------------------------|
| **Modules**（`import std;`）                   | C++23/26  | 替代 `#include`，模块化编译    | 所有新代码用模块；`src/<layer>/<module>.cppm` 仅导出必要接口 |
| **`std::expected<T, E>`**                      | C++23     | 函数返回结果 / 错误            | 错误处理首选返回类型；配合 monadic 操作链式组合（见 §3.5）   |
| **`std::generator`**                           | **C++23** | 懒序列 / 流式采集 / 查询迭代   | **协程主力**（见 §7）；替代手动迭代器与回调                  |
| **Concepts**                                   | C++20     | 模板约束                       | 泛型接口必须 `requires` 约束，禁用 `typename` 随意泛化       |
| **Coroutines（`co_yield`/`co_await`）**        | C++20     | 异步 / 流式 / 状态机           | 底层协程语义，`std::generator` 与 `task` 的基石              |
| **Deducing this（显式对象参数）**              | C++23     | 消除 const/ref 限定四重重载    | 工具类、访问器、CRTP 统一为单个模板成员                      |
| **`constexpr` / `consteval` / `constinit`**    | C++20/23  | 配置解析、协议常量、编译期计算 | 编译期可算尽编译期算；`consteval` 强制编译期求值             |
| **`std::jthread`**                             | C++23     | 采集 / IO 线程                 | 析构自动 `join`，RAII 线程                                   |
| **`std::mdspan`**                              | C++23     | 时序批量缓冲                   | 零拷贝多维视图                                               |
| **`std::ranges` + `views`**                    | C++20/23  | 序列变换                       | 与 `std::generator` 组合管道                                 |
| **`<format>` / `std::format`**                 | C++20/23  | 类型安全格式化                 | 替代 `printf` / `sprintf` / 字符串拼接                       |
| **`std::chrono` 日历 / 时区**                  | C++20     | 时间戳、时区转换               | 工业时序的时钟语义                                           |
| **`std::span` / `std::span<const std::byte>`** | C++20     | 连续缓冲区非拥有视图           | 接口传缓冲，禁止裸指针 + 长度                                |

#### 1.1.2 C++26 前沿特性（ **演进采用，按编译器支持渐进启用**）

| 特性                                              | 状态                                        | 用途                                     | 启用策略                                                                                                       |
|---------------------------------------------------|---------------------------------------------|------------------------------------------|----------------------------------------------------------------------------------------------------------------|
| **静态反射（P2996，`std::meta`、`^^`、`[: :]`）** | C++26 已采纳，GCC/Clang 实验性              | 协议自动编解码、审计字段序列化、配置反射 | **最大化使用**：测点 → `DataPoint` 自动映射、审计上下文自动展开；不支持时 `if constexpr` 切自研 trait（见 §8） |
| **`std::execution`（P2300 Senders/Receivers）**   | C++26 已采纳                                | 异步任务编排、并行管线、调度器           | MQTT IO、采集-传输-存储管线，**结构化并发基石**（见 §7.4）；不支持走 Asio 适配层                               |
| **契约（Contracts，P2900）**                      | C++26 演进中（GCC 需 `-fcontracts` 等开关） | 前置/后置条件、不变量                    | **接口约束首选**（见 §9）；不可用时代码等价降级为 `assert`/`ensures` 内联函数                                  |
| **`std::task` / 无栈协程完善**                    | C++26 演进中                                | 异步值类型                               | 与 `std::execution` 配套的异步计算                                                                             |
| **`import std;` + 标准库模块化**                  | C++26                                       | 编译加速、隔离                           | 默认开启                                                                                                       |

> **最大化采用原则**：GCC 16.2 / Clang 24 已支持的特性 **默认全开**，不因 MSVC 滞后而退化。未全量支持的特性通过 §1.2
> 特性开关隔离，保证所有工具链仍可编译。

> ⚠️ **诚实标注**：Networking TS / `std::network` **未进入 C++26**。ECAS 网络层通过 **redboltz-mqtt_cpp（基于 Asio）+
`std::execution` 适配** 实现，不等待标准 networking。

#### 1.1.3 禁止清单（ **过时特性 / 宏黑魔法一律拒绝**）

| 禁止项                                                                                    | 替代方案                                                   |
|-------------------------------------------------------------------------------------------|------------------------------------------------------------|
| 裸 `new` / `delete`、`malloc` / `free`                                                    | `unique_ptr` / `vector` / 值类型                           |
| 裸 `include`（新代码）                                                                    | Modules：`import std;` / `import ecas.foundation.error;`   |
| 裸拥有指针 / 裸句柄（`SSL*`、`EVP_*`、`FILE*`、裸 fd）                                    | RAII 封装 + 自定义 deleter                                 |
| `#define` 宏（除 `import` 相关，且 module 已消除 include guard）                          | `constexpr`、`consteval`、模板、`if constexpr`             |
| **宏黑魔法**：`do { ... } while(0)`、`##` 拼接、`__VA_ARGS__` 可变参技巧、`offsetof` 戏法 | 内联函数、模板、`constexpr` lambda、`std::source_location` |
| 宏定义"伪关键字"（`ECAS_UNUSED`、`ECAS_LIKELY`、`LIKELY` 等）                             | `[[maybe_unused]]`、`[[likely]]` / `[[unlikely]]` 标准属性 |
| 宏条件编译模拟模板特化                                                                    | `if constexpr`、concepts、`requires`                       |
| C 风格强制转换、`NULL`、`0` 作空指针                                                      | `static_cast` / `std::bit_cast`、`nullptr`                 |
| `printf` / `sprintf` / `itoa`                                                             | `std::format`、`std::to_string`                            |
| 裸 `std::thread`、`pthread_*`、手动 `join`/`detach`                                       | `std::jthread`、执行器                                     |
| 裸 `try/catch` 跨模块边界                                                                 | 边界处**仅一处**转为 `Result<T>`                           |
| 全局可变状态、`static` 非 POD                                                             | `constinit` 常量、依赖注入                                 |
| 手动引用计数、`goto`、变长数组（VLA）                                                     | 智能指针、`std::vector`                                    |
| 手动 `init/cleanup` 二段式资源                                                            | 构造即获取 + RAII                                          |
| **回调地狱 / 手动状态机**                                                                 | **协程 `std::generator` / `task`**                         |
| **手写样板编解码 / 反射**                                                                 | **静态反射 + Concepts**                                    |

### 1.2 编译选项（CMake，Conan toolchain）

#### 编译器版本与平台策略

| 优先级       | 编译器        | 平台                       | CI 角色                                                                         |
|--------------|---------------|----------------------------|---------------------------------------------------------------------------------|
| **首选**     | **GCC 16.2+** | Linux / Windows(MinGW-w64) | **主战场**：C++26 新特性完整验证、全量门禁                                      |
| **备选**     | **Clang 24+** | macOS / Linux              | 对标验证：可移植性、clang-tidy 静态分析；反射/execution 走降级分支              |
| **暂不考虑** | MSVC          | Windows                    | 对协程、`expected` 完整语义、静态反射、`std::execution`、契约支持滞后，拖累设计 |

> **关键**：不满足特性要求的编译器 **不应被 CI 门禁要求**，否则会产生因标准库未实现导致的假阴性。改用 **编译期特性探测 +
降级适配**（见 §7.6、§9）。

#### 编译选项

- 语言标准：`-std=c++26`（GCC/Clang/MinGW，需 GCC 16.2+ 才能完整支持协程与反射）；Clang 24 对齐
- 模块支持：GCC 16.2+ `-fmodules` + `-fmodule-mapper=...`，配套 `import std;`
- 契约开关（GCC）：`-fcontracts`（若可用），退化时降级断言仍生效
- 警告全开并视为错误：`-Wall -Wextra -Wpedantic -Werror`（GCC/Clang/MinGW）；启用新特性相关警告
- 关键额外开关：
    - `-Wnoexcept`：析构非 noexcept 报警
    - `-Wdeprecated`：任何使用禁止清单中的过时 API 报警
    - `-fsanitize=address,undefined,thread`（Debug CI，Linux GCC 16.2 全开；MinGW 用可用子集）
- 禁止：`-fno-exceptions`（本项目 **启用异常**，只是不让它跨模块边界逃逸）

#### 特性探测（ **不用宏黑魔法，用 `requires` / `__has_builtin` / 编译期常量**）

```cpp
// foundation/config.cppm —— 特性开关（编译期常量，非宏）
export module ecas.foundation.config;
export import std;

export namespace ecas::config {
    // 静态反射：GCC 16.2+ / Clang 24 实验性 / MSVC 未支持 → 编译期分支
    inline constexpr bool has_static_reflection =
#if defined(__cpp_static_reflection)
        true;
#else
        false;
#endif

    // Senders/Receivers：GCC 16.2+ 优先，Clang 24 部分
    inline constexpr bool has_execution =
#if defined(__cpp_lib_execution) && __has_include(<execution>)
        true;
#else
        false;
#endif

    // 契约：GCC -fcontracts 可用时启用运行时检查
    inline constexpr bool has_contracts =
#if defined(__cpp_contracts)
        true;
#else
        false;
#endif

    // 协程：GCC / Clang / MinGW 均已支持 std::generator（C++23）
    inline constexpr bool has_coroutines = true;
}
```

依赖这些开关的模块在 `if constexpr` 分支中 **提供降级实现**，保证所有工具链（含 Clang 24 降级分支、未来 MSVC）都能编译通过，且
**降级分支同样有测试覆盖**（见 §10）。

## 3. 错误处理（核心）

### 3.1 分层错误传递模型

```mermaid
flowchart LR
    L1[L1 设备 / 解析] -->|expected<Frame, ParseError>| L2[L2 协议<br/>反射编解码]
    L2 -->|expected<Point, Error>| L3[L3 采集<br/>协程管线]
    L3 -->|Result<void> + 警告队列| L4[L4 传输]
    L4 -->|expected<PublishReceipt, Error>| L5[L5 持久]
    L5 --> L6[L6 接口]
    L6 --> L7[L7 业务]
    L7 --> L8[L8 UI / API]
    L8 --> LOG[结构化日志 + 告警 + 审计]
```

**关键**：每一层 **可以丰富错误上下文**（追加位置、设备 ID、时间戳），但 **不可静默吞没**。最上层（L7/L8）负责 **决定**：重试 /
降级 / 告警 / 审计 / 展示给用户。

### 3.2 类型定义

```cpp
export module ecas.foundation.error;
export import std;

export namespace ecas::error {
    // 错误码（分层命名空间，避免撞码）
    enum class Code : std::uint32_t {
        ok = 0,
        device_open_failed = 1001,
        serial_timeout     = 1002,
        parse_invalid_frame = 2001,
        parse_unsupported   = 2002,
        buffer_full         = 3001,
        mqtt_disconnected   = 4001,
        tls_handshake_failed= 4002,
        iotdb_write_failed  = 5001,
        pg_transaction_failed = 5002,
        audit_sign_failed   = 7001,
    };

    // 结构化错误：码 + 消息 + 上下文（可携带嵌套原因）
    struct Error {
        Code                 code = Code::ok;
        std::string          message;
        std::source_location where = std::source_location::current();
        std::vector<std::pair<std::string, std::string>> context;
        std::unique_ptr<Error>                          cause;

        [[nodiscard]] static auto make(Code c, std::string msg,
                                       std::source_location loc = std::source_location::current())
            -> Error;

        [[nodiscard]] auto with(std::string key, std::string value) && -> Error;
        [[nodiscard]] auto nest(Error nested) && -> Error;
        [[nodiscard]] auto to_fields() const -> std::vector<std::pair<std::string, std::string>>;
        [[nodiscard]] auto to_string() const -> std::string;
    };

    // 结果别名（C++23 std::expected）
    template<typename T>
    using Result = std::expected<T, Error>;
}
```

### 3.3 使用规约

1. **对外函数一律返回 `Result<T>`**，绝不抛异常跨越模块边界。

```cpp
// ✅ 正确：失败通过返回值上送
[[nodiscard]]
auto parse_frame(std::span<const std::byte> buf)
    -> Result<ParsedFrame>;

// ❌ 禁止：把异常当控制流抛给上层
auto parse_frame(...) -> ParsedFrame { if(...) throw ParseException{...}; }
```

2. **`[[nodiscard]]` 强制**：所有 `Result` 返回必须被检查；未使用触发编译警告（升级为错误）。
3. **错误向上丰富上下文**（见《全局设计》§2.2 契约）。
4. **警告 ≠ 错误**：可恢复的异常状态进入 **警告队列**，不阻断主流程，但最终必须被上层消费。
5. **析构路径绝不失败**：析构 `noexcept`；释放资源失败 **仅记录日志**，不抛、不返回。
6. **异常仅限内部实现**：模块 **内部**可用异常 + RAII 做栈展开，但 **边界处统一转为 `Error`**。

### 3.4 错误码分层与审计

- 错误码按层分段（见 §3.2），便于定位归属与统计。
- **所有 Error 在上层落审计**（PG `audit_logs` + IoTDB 趋势），包含码、消息、上下文、cause 链。
- **警告同样向上**：底层产生 `Warning`，L7 决定告警等级并落审计。

### 3.5 `std::expected` 的现代化组合（monadic 操作）

C++23 的 `std::expected` 提供 `and_then` / `transform` / `transform_error` / `or_else` 等 monadic 操作， **消除逐层
`if (!r)` 样板**，让错误自动向上传播：

```cpp
// ✅ C++23 monadic：错误自动传播，仅书写成功路径
auto process(DataPoint p) -> Result<Stored> {
    return parse(p)
        .and_then([](auto&& pt)  { return batch(pt); })
        .and_then([](auto&& b)   { return store(b); })
        .transform_error([](Error e) {
            return std::move(e).with("stage", "process");
        });
}
```

**规则**：

- 成功链用 `and_then`（返回 `Result`）/ `transform`（返回普通值）
- 错误链用 `transform_error` / `or_else`，在边界统一丰富上下文
- **绝不**用宏模拟 `try/catch` 的"自动返回"（这是宏黑魔法），monadic 操作是语言原生方案

## 4. 日志与可观测性（向上管理）

### 4.1 原则

| 原则               | 说明                                                                         |
|--------------------|------------------------------------------------------------------------------|
| **底层不决定日志** | L1–L5 **不直接调用日志输出**；只产生 `Error` / `Warning`，由上层决定是否记录 |
| **结构化日志**     | 日志 = `{level, timestamp, module, code, message, context...}` 字段集合      |
| **单一入口**       | 唯一的 `Logger` 接口（`ILogger`），可注入（文件 / 控制台 / 远程）            |
| **可观测三件套**   | 日志（Log）+ 指标（Metrics）+ 追踪（Trace），均向上汇聚到 L7                 |

### 4.2 日志接口

```cpp
export module ecas.foundation.log;
export import std;
export import ecas.foundation.error;

export namespace ecas::log {
    enum class Level { trace, debug, info, warn, error, critical };

    struct Record {
        Level                                          level;
        std::string_view                              module;
        std::string                                   message;
        std::chrono::system_clock::time_point         ts;
        std::source_location                         where;
        std::vector<std::pair<std::string, std::string>> fields;
    };

    class ILogger {
    public:
        virtual ~ILogger() noexcept = default;
        virtual void emit(Record r) noexcept = 0;
        virtual void flush() noexcept = 0;
    };

    void set_logger(std::shared_ptr<ILogger> logger) noexcept;

    // ✅ 使用函数（非宏）：附带 source_location + 自动字段，拒绝 ECAS_LOG 宏黑魔法
    void emit(Level level, std::string_view module, std::string message,
              std::source_location loc = std::source_location::current());
}
```

> **设计取舍**：日志接口 **刻意不用宏**（`ECAS_LOG(...)` 展开为 `Record` 等属宏黑魔法范畴）。改用 `source_location`
> 默认参数 + 内联函数，达到同等效果且完全现代化。链式风格用 **builder 值类型**（`noexcept` 析构）而非宏。

### 4.3 调用链示例（错误 → 日志 → 审计）

## 5. RAII 与全生命周期管理（核心）

> 《全局设计》已确立 RAII 为第一性原则；本节给出 **强制编码规约**与 **验证手段**。

### 5.1 资源分类与拥有者

| 资源                                    | 拥有者（RAII 类型）                                              |
|-----------------------------------------|------------------------------------------------------------------|
| 内存                                    | `std::vector` / `std::string` / `std::unique_ptr`                |
| 文件 / 串口 / 设备                      | `std::unique_ptr<Handle, CustomDeleter>`                         |
| 套接字 / MQTT / IoTDB Session / PG 连接 | `MqttClient` / `IoTDBSession` / `PgConnection`（独占）           |
| 加密上下文                              | `EvpCtx` / `TlsContext`（自定义 deleter）                        |
| 锁                                      | `std::unique_lock` / `std::scoped_lock`                          |
| 线程                                    | `std::jthread`（C++23，析构自动 join）                           |
| 定时器                                  | `ScopedTimer`（析构取消 + 等待）                                 |
| 跨线程数据                              | `concurrentqueue`（值类型 / 智能指针元素）                       |
| 插件                                    | `std::unique_ptr<IPlugin>`                                       |
| **协程状态**                            | 协程帧由 `std::generator` / `task` 自动管理，析构即销毁（见 §7） |

### 5.2 编码规约

1. **构造即获取，析构即释放**：ctor 建立不变式；dtor `noexcept` 释放全部子资源。
2. **禁止二段构造**：无"构造后必须 `init()` 才可用"的类型；失败用工厂 `Result<unique_ptr<T>> create(...)`。
3. **拷贝 = delete，移动 = 显式**：独占资源 `= delete` 拷贝，仅 `T(T&&)` / `operator=(T&&)`，移动后源为"空而有效"。
4. **接口所有权清晰**：
    - 接收：`void consume(std::unique_ptr<Message>)`（转移）或 `void process(const Message&)`（借用）
    - 返回：`std::unique_ptr<IFoo> create()`（调用方拥有）
    - **绝不返回裸指针指向内部资源**
5. **自定义 deleter 优先**：`FILE*` / `SSL*` / `EVP_CIPHER_CTX*` / MQTT 句柄 → `unique_ptr<H, Deleter>`，Deleter
   `noexcept`。
6. **锁 / 并发**：`scoped_lock` / `unique_lock`；禁止手动 `lock/unlock`；共享数据用 `shared_ptr` + `mutex` 或 lock-free（
   `concurrentqueue`）。
7. **异常安全**：dtor 绝不抛；事务满足强保证，回滚由析构保证。
8. **禁止裸全局资源**：用 `call_once` + `unique_ptr`，退出确定性销毁；优先依赖注入。

### 5.3 生命周期状态图

```mermaid
stateDiagram-v2
    [*] --> Acquired: 构造即获取<br/>(ctor 成功 = 资源有效)
    Acquired --> InUse: 业务调用
    InUse --> InUse: std::move<br/>所有权转移，源置空
    InUse --> Released: 离开作用域<br/>析构 noexcept
    Released --> [*]: 确定性销毁
    Acquired --> [*]: 构造失败<br/>栈展开析构已获子资源
```

### 5.4 反例与正例

```cpp
// ❌ 反例：裸资源、手动 close、异常不安全（C 风格遗留）
void bad() {
    EVP_CIPHER_CTX* ctx = EVP_CIPHER_CTX_new();
    if (encrypt(ctx, ...) != 1) return;   // 泄漏
    EVP_CIPHER_CTX_free(ctx);
}

// ✅ 正例：RAII + Result + 自定义 deleter（无任何宏、无裸管理）
class EvpCtx {
public:
    EvpCtx() : ctx_(EVP_CIPHER_CTX_new()) {
        if (!ctx_) throw std::runtime_error("EVP init");   // 内部异常，边界处转 Error
    }
    ~EvpCtx() noexcept { EVP_CIPHER_CTX_free(ctx_); }

    EvpCtx(const EvpCtx&) = delete;
    auto operator=(const EvpCtx&) -> EvpCtx& = delete;
    EvpCtx(EvpCtx&& o) noexcept : ctx_(std::exchange(o.ctx_, nullptr)) {}
    auto operator=(EvpCtx&& o) noexcept -> EvpCtx& {
        if (this != &o) { EVP_CIPHER_CTX_free(ctx_); ctx_ = std::exchange(o.ctx_, nullptr); }
        return *this;
    }

    [[nodiscard]] auto encrypt(std::span<const std::byte> in)
        -> Result<std::vector<std::byte>>;

    auto get() const -> EVP_CIPHER_CTX* { return ctx_; }

private:
    EVP_CIPHER_CTX* ctx_;
};

auto do_encrypt(std::span<const std::byte> in) -> Result<std::vector<std::byte>> {
    auto ctx = EvpCtx{};              // 构造即获取
    return ctx.encrypt(in);            // 返回 Result；ctx 离开作用域必析构
}
```

### 6.1 模块划分（C++26 Modules）

每个模块一个 `.cppm`， **仅导出必要接口**；模块间依赖通过抽象接口（`ILogger`、`IStorageBackend`、`IDeviceDriver`...），禁止循环依赖。

### 6.2 接口设计规则

1. **接口即契约**（见 §9）：抽象类纯虚接口，实现类在 `.cpp` 内隐藏细节（PImpl 可选）。
2. **禁止返回裸拥有指针**：返回 `unique_ptr` / `expected<unique_ptr>` / `span`（非拥有视图）。
3. **虚析构 `noexcept`**：`virtual ~IFoo() noexcept = default;`
4. **参数 const 正确**：输入 `const T&` / `std::span<const byte>`；输出 `T&` 或返回值。
5. **接口不抛**：所有 `public` 接口返回 `Result<T>`；异常在 `.cpp` 实现内捕获转换。
6. **可测试**：依赖通过接口注入，便于 mock。
7. **用 deducing this 消除重载**（C++23/26）：

```cpp
// ✅ 一个成员覆盖 const/volatile/&/&& 四种限定
template<typename Self>
auto&& get_name(this Self&& self) {
    return std::forward<Self>(self).name_;
}
```

## 7. 协程与异步模型（核心，C++26 现代化重点）

> ECAS 的采集、传输、查询天然是 **流式 / 异步 / 延迟计算**场景，协程是表达力与性能的最佳平衡点。本节确立协程为
> **首选异步范式**（铁律 #5），并在 GCC 16.2 / Clang 24 / MinGW 上最大化采用。

### 7.1 协程选型一览

| 场景                             | 协程 / 类型                              | 说明                                        |
|----------------------------------|------------------------------------------|---------------------------------------------|
| 流式采集（设备 → 帧 → 点）       | `std::generator<T>`                      | 懒生成，按需产出，零拷贝                    |
| 历史/查询迭代（IoTDB/PG 结果集） | `std::generator<DataPoint>`              | 替代回调 + 手动迭代器，配合 `ranges::views` |
| 树形/层级遍历（设备拓扑）        | `std::generator` + `ranges::elements_of` | 对称转移，避免嵌套 suspend/resume 开销      |
| 异步 IO（MQTT 发布、网络读写）   | `task<T>` / `std::execution` sender      | 异步值类型，与执行器组合                    |
| 管线编排（采集→转换→传输→存储）  | `std::execution`（senders/receivers）    | C++26 结构化并发，编译期错误路由            |
| 并发聚合                         | `when_all` / `when_any`                  | 多设备并行采集                              |

### 7.2 `std::generator`：流式采集（懒序列）

**价值**：设备数据"源源不断"，传统方案要么缓冲全部（内存爆炸），要么回调分片（逻辑割裂）。`std::generator` 让采集函数
**像写同步循环一样写流式逻辑**，调用方按需拉取—— **既提升开发效率，又优化内存性能**。

```cpp
export module ecas.acquisition.pipeline;
export import std;
export import ecas.foundation.error;

export namespace ecas::acquisition {
    using namespace ecas::error;

    // ✅ 懒序列：设备原始帧流。不缓冲，调用方每次 co_yield 才推进
    auto read_frames(Device& dev) -> std::generator<RawFrame> {
        while (dev.is_open()) {
            auto buf = dev.read_some();        // 同步风格，协程自动挂起
            if (!buf) co_return;
            co_yield *std::move(buf);
        }
    }

    // ✅ 组合管道：解析 → 校验 → 点，全程懒执行（C++23 ranges + generator）
    auto parse_points(std::generator<RawFrame> frames)
        -> std::generator<Result<DataPoint>> {
        for (auto frame : frames) {
            auto r = parse_frame(frame);       // Result<DataPoint>
            co_yield r;                         // 逐条向上，不缓冲
        }
    }

    // 调用方：按需消费，可与 views 组合
    void pipeline(Device& dev) {
        auto points = read_frames(dev)
                    | std::views::filter([](auto&& f) { return f.valid(); })
                    | std::views::transform(to_point);

        for (auto&& p : points) {               // 每次迭代才驱动协程推进
            store(p);
        }
    }
}
```

**关键性质**：

- **懒求值**：只有 `for` 循环取迭代器时才执行到下一个 `co_yield`，节省内存
- **零拷贝**：`co_yield` 存储指针指向协程帧局部变量，不复制（注意生命周期，见 §7.6）
- **对称转移**（`ranges::elements_of`）：递归遍历层级设备拓扑时，避免每层 suspend/resume 嵌套开销

### 7.3 历史查询：懒加载结果集

存储层 `query` 返回 `std::generator<DataPoint>`，UI 层（L8）可 **边查边画图表**，无需等全量数据加载：

```cpp
auto query_history(const Query& q) -> Result<std::generator<DataPoint>> {
    co_return generate_points(session_, q);   // 工厂构造 generator
}

// UI 层：图表逐步渲染

    chart.append(point);                      // 逐点追加，响应即时
    if (user_cancelled()) break;              // 取消即停止拉取，资源自动回收
}
```

### 7.4 `std::execution`：结构化并发管线（C++26）

采集 → 转换 → 传输 → 存储构成 **异步管线**。C++26 的 `std::execution`（P2300 Senders/Receivers）提供 **类型级错误路由**（
`set_value` / `set_error` / `set_stopped`），编译期即确定错误处理路径：

```cpp
export module ecas.pipeline;
export import std;
export import std.exec;   // C++26 std::execution

export namespace ecas::pipeline {
    auto process_point(DataPoint p) -> Result<Stored> { /* ... */ }

    // 并行：多设备采集 when_all；任一失败 → 整体 error 通道
    auto run_acquisition(std::vector<Device> devices) {
        std::vector<Sender auto> senders;
        for (auto& dev : devices) {
            senders.push_back(
                just(dev)
                | then([](Device& d) { return read_frames(d); })
                | then([](auto frames) { return parse_points(frames); })
                | then([](auto points) { return store_batch(points); })
            );
        }
        return when_all(std::move(senders));    // 结构化并发
    }
}
```

**优势**：

- **错误自动路由**：`then` 只走成功路径，`upon_error` 处理错误，编译期确定
- **取消传播**：`set_stopped` 通道，取消一个子任务自动取消兄弟（管线取消语义统一）
- **调度器无关**：可挂接线程池 / GPU / 网络执行器，适配工业边缘 → 中心的异构硬件

> 编译器尚未完整支持 `std::execution` 时（如 Clang 24 部分支持），用 **Asio + 自研 sender 适配层**降级（redboltz-mqtt_cpp
> 已基于 Asio，无额外依赖）。降级分支同样有测试覆盖（§10）。

### 7.5 协程中的错误处理（与 `Result` 融合）

协程内部仍遵循铁律 #2： **对外不抛异常**。生成器产出 `Result<T>`，让错误随序列逐条上送：

```cpp
auto parse_points(std::generator<RawFrame> frames)
    -> std::generator<Result<DataPoint>> {
    for (auto frame : frames) {
        auto r = parse_frame(frame);
        if (!r) {
            co_yield std::unexpected{       // 错误作为序列元素上送，不抛
                std::move(r).error().with("stage", "parse")};
            continue;
        }
        co_yield *std::move(r);
    }
}

// 调用方：错误与值在同一序列中分流
for (auto&& result : parse_points(frames)) {
    if (!result) {
        audit::record(result.error());      // 错误向上（铁律 #3）
        continue;
    }
    store(*result);
}
```

### 7.6 协程生命周期规约（RAII × 协程）

协程帧本身是 RAII 资源（`std::generator` / `task` 析构即销毁帧），但 **悬挂引用**是协程特有陷阱，强制规则：

1. **`co_yield` 指向局部变量是安全的**（帧存活）；但 **不要把局部变量地址逃出协程生命周期**
2. **`co_await` 异步操作时，确保缓冲区/对象活到完成**：用 `std::shared_ptr` 或 `task` 链式持有
3. **生成器析构必须取消挂起操作**：`std::generator` 析构自动销毁帧，挂起中的 IO 须通过 `stop_source` / `set_stopped` 协作取消
4. **禁止跨协程裸共享可变状态**：共享数据用 `std::shared_ptr<const T>` + 互斥，或 immutable snapshot
5. **协程内禁用阻塞操作**：IO 必须 `co_await`（异步），否则阻塞整个调度器

```cpp
// ❌ 危险：co_yield 后局部 buf 可能因帧销毁而悬垂
auto bad() -> std::generator<std::span<const std::byte>> {
    std::vector<std::byte> buf = read();
    co_yield buf;   // buf 在下次恢复前可能因帧销毁而悬垂
}

// ✅ 安全：co_yield 值类型 / 拥有对象，所有权随生成器帧
auto good() -> std::generator<std::vector<std::byte>> {
    std::vector<std::byte> buf = read();
    co_yield std::move(buf);   // 值移动，无悬垂
}
```

### 7.7 协程 + 静态反射：协议零样板（C++26 演进）

静态反射（§8）让 `DataPoint` 的成员在编译期可见，协程管线可 **自动展开字段、自动映射测点**，无需手写样板：

```cpp
export module ecas.protocol.reflect;
export import std;
export import std.meta;   // C++26

export namespace ecas::protocol {
    struct DataPoint {
        std::string  device_id;
        std::int64_t timestamp_ns;
        double       value;
        std::string  quality;
    };

    // 编译期遍历成员 → IoTDB 树形路径 + 审计字段（反射，零手写）
    template<typename T>
    consteval auto to_audit_fields(const T& obj) {
        std::vector<std::pair<std::string, std::string>> fields;
        for constexpr (auto member : std::meta::nonstatic_data_members_of(^^T)) {
            fields.emplace_back(
                std::meta::identifier_of(member),
                to_string(obj.[:member:])
            );
        }
        return fields;
    }
}
```

> 编译器（Clang 24 实验性）尚未支持时，用 **C++20 concepts + 自研 trait 模板**降级（标准元编程， **非宏黑魔法**），待反射落地一键切换。

## 8. 静态反射（C++26）

> 静态反射是 **减少样板、提升代码质量** 的关键特性，ECAS 在 GCC 16.2 上最大化使用，Clang 24 / MinGW 通过特性开关降级。

### 8.1 应用点

| 场景               | 反射带来的收益                                                 |
|--------------------|----------------------------------------------------------------|
| **协议编解码**     | `DataPoint` / 报文结构成员自动序列化，无需手写 `encode/decode` |
| **审计字段展开**   | 任意结构自动展开为 `{name: value}` 审计上下文                  |
| **配置反序列化**   | YAML/JSON → 结构体，成员自动映射                               |
| **IoTDB 测点映射** | 结构体成员 → 树形路径 `root.ecas.{site}.{device}.{field}`      |
| **测试 / 校验**    | 成员自动遍历做字段级校验                                       |

### 8.2 降级策略

```cpp
export module ecas.foundation.reflect;
export import std;
export import ecas.foundation.config;   // has_static_reflection

export namespace ecas::reflect {
    // 统一入口：编译期按特性开关分发
    template<typename T>
    consteval auto member_names() {
        if constexpr (config::has_static_reflection) {
            // GCC 16.2：真实静态反射
            return std::meta::nonstatic_data_members_of(^^T)
                 | std::views::transform(&std::meta::identifier_of);
        } else {
            // Clang 24 / MinGW 降级：手写 trait（concepts 约束）
            return typename traits::member_names_of<T>::value;
        }
    }
}
```

> 降级分支是 **标准的 concepts + trait 元编程**，不是宏黑魔法；且 **必须有测试覆盖**（见 §10），保证行为一致。

## 9. 契约（C++26，铁律 #6）

> 契约是 **提升代码质量、把 Bug 消灭在编译期/运行初期** 的核心手段。ECAS 把所有对外接口的约束声明为契约。

### 9.1 策略

- **首选 C++26 契约**（`pre` / `post` / `contract_assert`，GCC 16.2 `-fcontracts`）
- **降级**：不可用时代码等价写为 `[[assert: ...]]` 或内联 `ensures` 函数—— **逻辑不降级，只降级检查机制**
- **契约是接口的一部分**：出现在模块接口（`.cppm`）中，调用方可见

### 9.2 示例

```cpp
export module ecas.acquisition.driver;
export import std;
export import ecas.foundation.contracts;   // 契约降级封装

export namespace ecas::acquisition {
    // ✅ 前置条件 + 后置条件，编译期/运行期双保险
    [[nodiscard]]
    auto write_point(const DataPoint& p) -> Result<void>
        // 前置：device_id 非空、timestamp 合理
        pre(p.device_id.empty() == false)
        pre(p.timestamp_ns > 0)
        // 后置：成功时返回 ok
        post(r: r.has_value() == (r.value_or({})._ == 0))
    {
        if (!is_valid(p)) {
            return std::unexpected{Error::make(Code::parse_invalid_frame, "invalid point")};
        }
        return do_write(p);
    }

    // 不变量：类型层面的约束用 Concepts
    template<typename T>
    concept DataPointLike = requires(const T& t) {
        { t.device_id } -> std::convertible_to<std::string_view>;
        { t.timestamp_ns } -> std::convertible_to<std::int64_t>;
        { t.value } -> std::convertible_to<double>;
    };
}
```

### 9.3 契约降级封装（拒绝宏黑魔法）

```cpp
export module ecas.foundation.contracts;
export import std;
export import ecas.foundation.config;

export namespace ecas::contracts {
    // ✅ 用内联函数 + requires 封装，不用宏
    template<typename Pred>
    constexpr void requires_that(Pred pred, std::source_location loc = std::source_location::current()) {
        if (config::has_contracts) {
            // 真实契约：交由编译器 -fcontracts 处理（此处仅为占位示意）
            if (!pred()) throw std::logic_error("contract violated");  // 边界转 Error
        } else {
            // 降级：assert（NDEBUG 下可剔除）
            assert(pred());
        }
    }
}
```

> **注意**：降级用 `assert` / 内联函数，但 **逻辑与真实契约完全一致**——不因工具链差异改变程序语义。这正符合铁律
> #6"契约即接口的一部分"。

### 9.4 契约覆盖要求

- 所有 `public` 接口必须有前置条件（参数合法性）
- 所有返回 `Result<T>` 的接口必须有后置条件（成功/失败语义）
- 资源类型必须有不变量（"构造完成即有效 / 析构后不可使用"）
- 契约违反 → 转为 `Error`（`Code::contract_violation`）→ 向上 → 落审计

## 10. 并发模型

- **线程**：`std::jthread`（RAII，析构 join）；采集、MQTT IO、业务各一线程池。
- **数据管道**：`concurrentqueue`（lock-free），元素为 `unique_ptr` / 值类型；与协程 `channel` 互操作。
- **共享状态**：`std::shared_ptr<const T>` + `std::mutex`，或 immutable snapshot。
- **任务编排**： **`std::execution`（C++26）异步管线**（见 §7.4）；协程（`generator` / `task`）用于流式采集。
- **结构化并发**：`when_all` / `when_any` 聚合多设备任务，取消语义统一。
- **禁止**：裸 `std::thread`、裸 `pthread`、手动 `join`/`detach`、全局可变状态、数据竞争、协程内阻塞调用。

- 每条错误码至少一条失败路径用例
- 每个 RAII 类型断言资源引用计数归零
- 警告被正确向上消费（不丢失、不重复）

## 12. 编码规约速查（落地检查清单）

- [ ] 无裸 `new`/`delete`、`malloc`/`free`
- [ ] 无裸 `SSL*` / `EVP_*` / `FILE*` / 裸 fd 作为拥有者
- [ ] 析构函数一律 `noexcept`
- [ ] 资源类型拷贝 = delete，移动 = 显式
- [ ] 对外接口返回 `Result<T>` / `std::expected`，`[[nodiscard]]`
- [ ] 无裸露异常跨模块边界（边界处有 `try/catch` 转 `Error`）
- [ ] 错误向上丰富上下文，不吞没；警告被上层消费
- [ ] 底层不直接打日志，仅产生 `Error`/`Warning`
- [ ] **无 `#define` 宏**（除 module 相关，且已非黑魔法）
- [ ] 使用 C++26 modules / concepts / `expected` / `generator` / `execution` / 反射 / 契约
- [ ] **异步 / 流式优先用协程**（GCC 16.2 / MinGW 全量验证；Clang 24 降级验证）
- [ ] 协议编解码 / 审计字段优先用 **静态反射**
- [ ] 对外接口声明 **契约**（前置/后置/不变量），真实契约与降级逻辑一致
- [ ] 通过 `config::has_*` 特性开关隔离未全量支持的特性，保证所有工具链可编译
- [ ] 特性开关 `on/off` **双分支均有测试覆盖**
- [ ] 接口通过抽象类隔离，依赖注入，可 mock
- [ ] 全部依赖来自 `conandata.yml`，无系统级硬编码
- [ ] 许可证 ∈ {Apache 2.0, MIT, BSL, BSD, LGPLv3+}
- [ ] **编译器策略**：GCC 16.2+ 首选 / Clang 24+ 备选 / MSVC 暂不考虑；CI = Linux + Windows (MinGW) + macOS
