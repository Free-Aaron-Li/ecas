# shared — 跨端共享契约

> 状态：**占位目录**（2026-11-09 建立）。目前只放约定；首个共享产物（OpenAPI 快照）待 `web/backend` 接口冻结后生成。

## 放什么

只放**被两个及以上端（`cpp/` / `web/` / `miniapp/`）同时消费**的东西：

| 内容 | 形式 | 谁生成 |
|---|---|---|
| HTTP 接口契约 | OpenAPI 3.1 JSON（`openapi.json`） | 由 `web/backend` 导出，**不手写** |
| 协议常量与错误码 | `protocol/` 下的 `.hpp` + `.ts` + `.json` 单源 | 人工维护，三端引用 |
| 字段口径 | 单位、量程、换算公式、时间戳时区（`units.md`） | 人工维护 |
| 设计 token | 颜色 / 间距 / 字号（`tokens.json`） | 人工维护，Web 与小程序共用 |

## 不放什么

- 业务逻辑实现（各端自己实现调用，不共享代码）；
- 某一端专有的组件、样式、脚本；
- 数据库 schema（属 `web/backend` 或后续平台端）；
- 密钥、证书、环境变量样例（属部署配置，见 `deploy/`）。

## 铁律

1. **单一事实源**：同一份契约只允许存在一处，其它端通过生成或引用获得，禁止复制粘贴后各改各的。
2. **生成物不手改**：`openapi.json`、从它生成的类型文件都带「generated」头，改动必须回到生成端。
3. **破坏性变更要留痕**：字段删除/改名/单位变化，先在此目录的 `CHANGELOG.md` 记录并说明各端适配情况，再改。
4. **只增不改**：能被旧版本端容忍的字段新增优先；不能容忍的必须升版本号（`/v2`）。

## 目录（预期）
