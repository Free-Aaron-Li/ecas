# 从打开项目到上线 · 分步操作手册

> 配套文档：[`VSCode远程编辑教程.md`](./VSCode远程编辑教程.md)（讲原理、目录、红线、排错）。
> 本文只讲**手怎么动**：打开 → 本地跑 → 热加载 → 推到服务器 → 回传。
> 全部命令于 **2026-11-05 在先生本机 / `ubuntu-super` 实测通过**（标 ✅ 的为当轮实跑验证）。

## 0. 先选一条路

| 我想… | 走这条 | 需要 |
|---|---|---|
| 只看看代码、改注释 | **A. 纯浏览**（第 1 步的"远程打开"） | 远程窗口，不用构建 |
| 改界面 / 调样式，想立刻看到效果 | **B. 本地开发**（2–4 节） | 本机 PostgreSQL 55432 |
| 改后端逻辑，要在真数据上验 | **B → C**（本地改，本地验，再推） | 同上 + 部署脚本 |
| 线上急着修一行 | **D. 远程直接改**（5–6 节） | SSH + sudo 口令 |
| 前端改了要上线 | **B 的最后一步 + E 的推送** | `pnpm build` |

**铁律**：一次只认一边为主（要么以 Mac 仓库为准，要么以服务器为准），改完**必须回传**。
详见 [`VSCode远程编辑教程.md` §7](./VSCode远程编辑教程.md)。

## 2. 本地跑起来（第一次约 10 分钟，之后 30 秒）

### 2.1 起数据库（本机 PostgreSQL，端口 55432）

```bash
brew services list | grep postgres          # 看状态
brew services restart postgresql@18
pg_isready -p 55432                          # → accepting connections
psql -p 55432 -U ecas -d ecas_dev -tAc "select count(*), max(ts) from raw_reading"
# ✅ 期望：377 | 2026-09-26 09:27:10+08（快照数据，stale 属正常）
```

**起不来就先查假锁**（✅ 2026-11-05 踩过）：

```bash
tail -20 /opt/homebrew/var/log/postgresql@18.log
# 若见 FATAL: lock file "postmaster.pid" already exists，且 HINT 里的 PID 已被别的进程复用：
cp -p /opt/homebrew/var/postgresql@18/postmaster.pid /tmp/postmaster.pid.stale-$(date +%s)
rm -f /opt/homebrew/var/postgresql@18/postmaster.pid
brew services restart postgresql@18
```

> 想换成本机的**新鲜数据**（覆盖快照，慎用于对比实验）：

```bash
ssh -o ControlPath=none ubuntu-super \
  'docker exec ecas-db pg_dump -U ecas -d ecas --no-owner --no-privileges --clean --if-exists' \
  | psql -X -p 55432 -U ecas -d ecas_dev
```

### 2.2 起后端（FastAPI，8080）

```bash
cd /Users/lijc/source/qt/ecas/web/backend
ECAS_ALLOW_NO_AUTH=1 uv run uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload
```

> 🔴 **`ECAS_ALLOW_NO_AUTH=1` 不能省**。`ECAS_AUTH_TOKEN` 为空时后端是 **fail-closed**：
> `/api/*` 一律 503 并回 `服务未配置访问令牌（ECAS_AUTH_TOKEN 为空）：已按 fail-closed 拒绝。本机开发请显式设 ECAS_ALLOW_NO_AUTH=1。`
> （`/healthz` 不受影响，所以"healthz ok 但页面没数据"就是想省这个变量。）

验证（另一个终端）：

```bash
curl -s http://127.0.0.1:8080/healthz                      # ok
curl -s http://127.0.0.1:8080/api/health | head -c 200     # ✅ rows_total 377 / stale true / last conc 49.88
```

### 2.3 起前端（Vite，5173，带热更新）

```bash
cd /Users/lijc/source/qt/ecas/web/frontend
pnpm dev        # ✅ VITE v8.3.1 ready in 133ms
```

打开 **http://127.0.0.1:5173/** —— 这就是开发版看板，`/api`、`/healthz`、`/ws` 已由
`vite.config.ts:12-14` 代理到 8080（所以只要后端在跑，页面就有真数据）。

### 2.4 不想开两个终端？用后端托管构建产物（单端口）

```bash
cd /Users/lijc/source/qt/ecas/web/frontend && pnpm build     # 产出 dist/
# 后端重启后 http://127.0.0.1:8080/ 直接就是看板
```

## 3. 热加载怎么看（改完不用重启）

| 改哪里 | 怎么生效 | 看什么 |
|---|---|---|
| `web/frontend/src/**.tsx` | **保存即生效**（HMR，不用刷新） | 浏览器画面立即变；改动过大 Vite 自动整页刷新 |
| `web/backend/app/**.py` | 后端加了 `--reload` ⇒ **自动重启** | 终端出现 `WARNING: WatchFiles detected changes in 'app/convert.py'. Reloading...`（✅ 实测） |
| `web/frontend/vite.config.ts` | 需要**手动重启** `pnpm dev` | 配置不进 HMR |
| 数据库内容 | 不热更新 | 重跑 2.1 的 `pg_dump` 覆盖命令 |
| 服务器上的镜像 | 不热更新（见第 5 节） | 必须 build + restart |

**推荐的改法节奏**：

1. 前端：`pnpm dev` 开着 → 改 `components/` → 浏览器即时看；
2. 后端：`uv run uvicorn ... --reload` 开着 → 改 `app/` → 看终端重启日志 → `curl` 验接口；
3. 都满意了 → `pnpm build` → 推服务器（第 6 节）。

> 后端调试小技巧：想打断点就用 VS Code 的 Python 调试（本机已装 ms-python 套件），
> 或用 `uv run python -c "from app.convert import ..."` 直接试换算函数。

## 5. 在服务器上改并让改动生效

前提：已在远程窗口打开 `/opt/ecas`（1.2）。按改动类型选命令，**全部在远程终端里跑**。

### 5.1 改后端 `backend/app/*.py`

```bash
cd /opt/ecas
# 1) 语法自检（镜像里没有 pytest，app/ 只读，不能用 compileall）
docker compose run --rm --no-deps --entrypoint python api \
  -c "import ast,pathlib; [ast.parse(p.read_text()) for p in pathlib.Path('app').rglob('*.py')]; print('syntax ok')"
# 2) 重建镜像
docker compose build api          # ✅ 0.7s（全缓存时）
# 3) 应用（root 才读得到 credentials/700）
sudo systemctl restart ecas-stack
# 4) 验收
curl -s http://10.10.10.11:18080/healthz
docker compose logs -f --tail=50 api
```

### 5.2 改采集器 `collector/`

```bash
docker compose build collector && sudo systemctl restart ecas-stack
docker compose logs -f --tail=80 collector
```

### 5.3 改 RTU 主站 `rtu-master/rtu_master.py`

代码是**挂载**进容器的，不用重建镜像：

```bash
docker restart ecas-rtu-master
docker logs --tail=50 ecas-rtu-master
tail -n 3 /opt/ecas/rtu-master/logs/rtu-live.jsonl     # 确认还在出帧
```

### 5.4 改流量计入库 `flow/flow_ingest.py`（宿主机 systemd）

```bash
sudo systemctl restart ecas-flow-ingest
systemctl status ecas-flow-ingest --no-pager | head -12
```

### 5.5 改前端

前端源码不在服务器上 ⇒ **在 Mac 上改 + build + 推 dist**（第 6 节），推完浏览器 `Cmd+Shift+R`。

### 5.6 改 SQL

`sql/*.sql` 不会自动执行（只有 `001_init.sql` 在空库首次初始化时挂载执行）。新增 `005_xxx.sql` 后手工跑：

```bash
docker exec -i ecas-db psql -U ecas -d ecas < /opt/ecas/sql/005_xxx.sql
```

## 6. 推送到服务器（Mac 上执行）

### 6.1 正规路：`deploy.sh`（推荐）

```bash
cd /Users/lijc/source/qt/ecas

web/deploy/ubuntu/deploy.sh push     # 组装 + rsync 到 ubuntu-super:/opt/ecas（不含凭据）
web/deploy/ubuntu/deploy.sh build    # 目标机 docker compose build
web/deploy/ubuntu/deploy.sh up       # 装/启 systemd 单元（要 sudo 口令，密钥卷里）
web/deploy/ubuntu/deploy.sh check    # 端到端自检
```

- 只改后端 → `push` + `build` + `up` 就够；只改前端 → `push` 完就生效（api 只读挂载 `frontend-dist/`，**不用重启**）。
- 一把梭：`web/deploy/ubuntu/deploy.sh all`（push + creds + build + up + check）。
- 其它子命令：`stage`（只组装不传）/ `creds` / `backup` / `watchdog` / `logs` / `preflight`（只读体检）。
- 环境变量：`HOST`（默认 `ubuntu-super`）、`VAULT`（默认 `/Volumes/keys`）、`STAGE`（默认 `/tmp/ecas-stage`）。

**`push` 会覆盖**：`backend/app`、`backend/*`、`collector/*`、`sql/*.sql`、`frontend-dist/`、
`secrets/ca.crt`、`systemd/` `watchdog/` `backup/` `docker-compose.yml`。
**`push` 不会碰**：`flow/`、`rtu-master/`、`mqtt/`、`credentials/`、`.env`（见教程 §7.1）。

### 6.2 快修路：单文件 rsync（不等整套构建）

```bash
cd /Users/lijc/source/qt/ecas
R='ssh -o ControlPath=none'

# 仅后端某文件
rsync -av -e "$R" web/backend/app/convert.py ubuntu-super:/opt/ecas/backend/app/
ssh -o ControlPath=none ubuntu-super 'cd /opt/ecas && docker compose build api && sudo systemctl restart ecas-stack'

# 仅前端产物
rsync -a --delete -e "$R" web/frontend/dist/ ubuntu-super:/opt/ecas/frontend-dist/

# 仅 RTU 主站（挂载，无需重建）
rsync -av -e "$R" scripts/485/rtu_master.py ubuntu-super:/opt/ecas/rtu-master/
ssh -o ControlPath=none ubuntu-super 'docker restart ecas-rtu-master'
```

> 走 6.2 之后**一样要回传 Mac**（如果你是在服务器上改的）；从 Mac 推出去的不需要回传。

### 6.3 推完必验三条

```bash
curl -s http://10.10.10.11:18080/healthz           # ok
curl -s http://10.10.10.11:18080/api/health | head -c 200   # rows_total / last ts 对得上
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" http://10.10.10.11:18080/   # 200 821
```

## 9. 坑清单（都踩过）

| 现象 | 原因 | 处置 |
|---|---|---|
| `/healthz` ok 但页面没数据、`/api/*` 503 | 后端 fail-closed，缺 `ECAS_ALLOW_NO_AUTH=1` | 按 2.2 重起 |
| `pg_isready -p 55432` 无响应 | 陈旧 `postmaster.pid` 假锁 | 按 2.1 删锁重启 |
| 远程窗口连不上 / 卡在 Installing | VS Code < 1.144.1 的 server 包在 CDN 上是坏的（HTTP 400） | 升级 VS Code（现为 1.145.0 ✅） |
| `docker compose up -d` 报读不到 `credentials/` | 该目录 700 root，`ubuntu` 用户无权限 | 一律用 `sudo systemctl restart ecas-stack` |
| 改了后端没变化 | 忘了 `build`（镜像没重建）或没 restart | 5.1 的 1→4 步 |
| 改了前端没变化 | 没 `pnpm build` 就 rsync，或浏览器缓存 | 重新 build 推送 + `Cmd+Shift+R` |
| 远程改完，下次部署被"回滚" | `push` 覆盖了 `backend/app` 等 | 收工按第 7 节拉回并提交 |
| `flow/`、`rtu-master/` 两边不一致 | 这两个目录 `push` 不覆盖 | 每次改完手动 rsync 双向对齐 |
| 本机 `ssh`/`rsync` 报 ControlSocket 错 | 沙箱不许写 ControlMaster socket | 加 `-o ControlPath=none` |
