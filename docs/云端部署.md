# 云端部署（腾讯云 · OpenCloudOS 9.4）

> 建立日期：2026-09-26 ｜ 目的：把 `web/` 这一套（FastAPI 后端 + React 看板 + 报警引擎）
> 部署到**采集链路所在的那台云服务器**上，让数据落库、报警判定的地方就是数据住的地方。

> 开发机那一侧见 [`本地开发环境.md`](./本地开发环境.md)；现场采集链路见 [`485仪表接入SOP.md`](./485仪表接入SOP.md)。

### 进程与数据流

```
DPRO-66 浓度计 ── RS485/Modbus ── 塔石 TAS-KS-301 DTU ── 4G ── MQTT
                                                  │
                    ┌─────────────────────────────┘
                    ▼
        mosquitto 2.0.18（0.0.0.0:1883）
                    │  订阅主题 dpro66
                    ▼
        dpro66_monitor.sh（把原始值写库，原始值不动）
                    │
                    ▼
        PostgreSQL 16  ecas.raw_reading(model, ts, raw)
                    │
                    ▼
        ecas-web.service（FastAPI + 报警引擎，127.0.0.1:8080）
                    │  换算 / 补偿 / 阈值判定全在这层
                    ▼
        看板（同一进程托管 dist/）── SSH 隧道 ──> 开发机浏览器
```

**换算只在看板这一侧做一次**：库里永远只存 `raw`（uint16 原始值），
`浓度 = (raw − 4000) ÷ 160 + 0.3`、报警阈值、断线/超量程判据都在后端，
所以口径改了不用回填历史数据。

## 2. 首次部署做了什么（2026-09-26，一次性）

1. **云服务器装 uv**（原来既没有 uv 也没有 pip3，系统 Python 是 3.11）：

   ```bash
   curl -LsSf https://astral.sh/uv/install.sh | sh    # → /root/.local/bin/uv
   ```

2. **同步代码**（`backend/` 与 `frontend/` 必须同级，`main.py` 靠相对路径找 `dist/`）：

   ```bash
   rsync -az -e 'ssh -o ControlMaster=no' --delete \
     --exclude .venv --exclude __pycache__ --exclude .pytest_cache --exclude .env \
     web/backend/ ecas:/root/ecas-web/backend/
   rsync -az -e 'ssh -o ControlMaster=no' --delete \
     web/frontend/dist/ ecas:/root/ecas-web/frontend/dist/
   ```

   > ⚠️ `-e 'ssh -o ControlMaster=no'` 不能省：复用控制套接字时 rsync 会试图
   > 在 `~/.ssh/controlmasters/` 建本地 socket，在受限环境里直接失败。

3. **装依赖**：`cd /root/ecas-web/backend && uv sync --frozen --no-dev`
   —— 23 个包，与开发机**同版本**（psycopg 3.3.6、pydantic 2.13.5、uvicorn 0.54.0…）。

4. **写环境文件** `/root/ecas-web/ecas-web.env`（`chmod 600`，模板见 `web/deploy/cloud.env.example`）：

   ```
   ECAS_DSN=postgresql://ecas@127.0.0.1:5432/ecas
   PGPASSFILE=/root/.pgpass          # 口令不进命令行、不进仓库
   ECAS_MODEL_NAME=DPRO-66
   ECAS_HOST=127.0.0.1               # 只监听回环，对外靠 SSH 隧道
   ECAS_PORT=8080
   ECAS_AUTH_TOKEN=<token_urlsafe(32)>
   ECAS_ALARM_SCAN=1                 # 报警引擎：每分钟扫一遍
   ECAS_ALARM_SCAN_SECONDS=60
   ```

5. **装 systemd 单元**（仓库副本 `web/deploy/ecas-web.service`）并切换：

   ```bash
   systemctl disable --now ecas-api.service     # 旧的单文件 api.py，单元保留以便回滚
   systemctl enable --now ecas-web.service
   ```

   单元里的两个刻意选择：

   - **`--no-access-log`**：uvicorn 的访问日志会把查询串整条打出来，而看板与
     WebSocket 的令牌就在查询串里（浏览器不能给 WS 加请求头），开着等于把令牌写进
     journal。关掉后仍能看到应用自己记的「拒绝未授权 WebSocket/Api（来源 IP）」。
   - 硬化：`NoNewPrivileges` / `PrivateTmp` / `ProtectSystem=full`；`Restart=always`。

## 3. 日常：部署一次

```bash
web/scripts/deploy-to-cloud.sh                # 构建前端 → 同步 → uv sync → 重启 → 自检
web/scripts/deploy-to-cloud.sh --no-build     # 只改了后端时跳过前端构建
HOST_ALIAS=ecas web/scripts/deploy-to-cloud.sh
```

脚本自检会打：`/healthz` → 200、`/api/auth` → `auth_required: true`、
不带令牌的 `/api/health` → 401、首页 → 200。**幂等**，重复跑输出 `Checked 23 packages`。

### 看板怎么打开（隧道）

后端只监听回环，所以从开发机看云端看板要开一条隧道：

```bash
ssh -L 18080:127.0.0.1:8080 ecas      # 本机 8080 常被本地开发服务占着，所以用 18080
# 然后浏览器打开 http://127.0.0.1:18080/
```

看板会先问 `/api/auth`：需要令牌而本机没有 → 弹「需要访问令牌」。有三种进法：

```bash
# ① 直接读令牌（只有 root 能读）
ssh ecas 'grep ECAS_AUTH_TOKEN /root/ecas-web/ecas-web.env'

# ② 一键直链：令牌从地址栏读进 localStorage 后立刻抹掉地址栏
open "http://127.0.0.1:18080/?token=<令牌>"

# ③ curl（三种带法都支持）
curl -H "Authorization: Bearer $T" http://127.0.0.1:18080/api/health
curl "http://127.0.0.1:18080/api/health?token=$T"
curl --cookie "ecas_token=$T" http://127.0.0.1:18080/api/health
```

令牌轮换：改 `ecas-web.env` 里的 `ECAS_AUTH_TOKEN` → `systemctl restart ecas-web`
（浏览器侧点顶栏「清除令牌」重输）。

### 查状态与日志

```bash
systemctl status ecas-web --no-pager
journalctl -u ecas-web -n 100 --no-pager        # 报警引擎的扫描记录也在这里
curl -s http://127.0.0.1:8080/healthz
ssh ecas 'systemctl list-timers ecas-*'
```

## 4. 回滚

```bash
systemctl disable --now ecas-web.service
systemctl enable --now ecas-api.service        # 回到早期的单文件 api.py（127.0.0.1:8080）
```

两个单元不会互抢端口（都绑 8080），**切换时必须一停一起**。
数据库侧无需任何动作：`ecas-web` 只读 `raw_reading`，另外两张表
（`alarm_event` / `alarm_config`）是它自己建的，删掉不影响采集。

## 5. 安全现状与待办

- 后端 / 数据库 / 旧的 api 全绑 `127.0.0.1`，对外只有 22 与 1883；

- 令牌比较按 UTF-8 字节做常量时间比较；非 ASCII 令牌只走查询串（协议限制）。
