## 三、常用命令

### 1. 现场实时看浓度（前台，临时）

```bash
cd /root/ecas
# 口令从加密凭据取（本机在 /Volumes/keys/ecas/mqtt.toml），经环境变量传入，不要写进命令行
MQTT_USER=ecas MQTT_PASS="$(awk -F'"' '/^password/{print $2}' /Volumes/keys/ecas/mqtt.toml)" \
  ./scripts/dpro66_monitor.sh -t dpro66
```

### 2. 常驻监视（systemd，推荐）

```bash
systemctl status ecas-monitor.service --no-pager | head -12
systemctl restart ecas-monitor.service
tail -f /root/ecas/logs/dpro66_monitor.log          # 数据行
journalctl -u ecas-monitor.service -n 20 --no-pager # 服务自身报错
```

> 口令由 `LoadCredentialEncrypted=mqtt-pass:/root/ecas/credentials/mqtt-pass.cred` 解密后交给 `monitor-service.sh`，**服务器上没有明文口令文件**。
> 判断凭据对不对，仍看日志「数据来源」行：**「用户 ecas」**＝带账号；**「（匿名）」**＝没拿到口令（此时认证已开 ⇒ 被拒、永远没有数据）。

### 3. 后端接口 / 看板

### 7. 查数据库（原始值 / 浓度，只读）

```bash
# 有没有数据、最后一条什么时候、值多少
psql -h 127.0.0.1 -U ecas -d ecas -c "SELECT model, ts, raw FROM raw_reading ORDER BY ts DESC LIMIT 20;"
# 一条命令看规模 + 最新
psql -h 127.0.0.1 -U ecas -d ecas -tAc "SELECT count(*)||' 行，最新 '||max(ts) FROM raw_reading;"
# 就地换算成浓度（不落库，只在查询里算；⭐ 09-26 现役补偿 +0.3 加在浓度上）
psql -h 127.0.0.1 -U ecas -d ecas -c "SELECT ts, raw, raw/1000.0 AS ma, round((raw-4000)/160.0 + 0.3, 3) AS conc FROM raw_reading ORDER BY ts DESC LIMIT 20;"
# 最近 24 小时统计（只算有效区间，别让断线行把均值拖走）
psql -h 127.0.0.1 -U ecas -d ecas -c "SELECT count(*) n, round(avg((raw-4000)/160.0+0.3),3) avg, min(raw), max(raw) FROM raw_reading WHERE ts > now()-interval '24 hours' AND raw BETWEEN 4000 AND 20500;"
systemctl status postgresql --no-pager | head -3
```

> ⭐ 库里**只有 `model / ts / raw` 三列**：mA、浓度、补偿、断线/超量程判定**全部在后端算**（改补偿不动历史数据、不用重跑）。
> 现成查询见 `/root/ecas/sql/002_queries.sql`（8 条，含换算预览与数据缺口）。
> 口令走 `/root/.pgpass`（600），**不需要也不要把口令写进命令**。`psql` 若被问到密码，说明 `.pgpass` 丢了、权限不是 600、或**库名字段没写成 `*`**。
> 监视脚本落库默认**开**（`--no-db` 可关）；表结构与口径见 SOP `§八·C`，运维见 `§八·D`。

### 8. 落库自检 / 应急重启监视

```bash
# ① 落库自检：发一帧假报文走「MQTT → 监视脚本 → 数据库」全链路，自动删掉测试行
read -r -s -p 'MQTT 口令: ' P; echo; printf '%s\n' "$P" | /root/ecas/scripts/test_db_insert.sh
#   ⇒ 退出码 0=通过 ｜ 3=没进库 ｜ 2=用法/发布错 ｜ 环境变量 KEEP=1 可保留测试行

# ② 应急重启（systemd 之外的手动方式；口令走管道，一行）
printf '%s\n' "$MQTT_PASS" | /root/ecas/scripts/start-monitor.sh
#   ⛔ 别用 `ssh 'bash -s' <<EOF` 里再 `read` 口令：heredoc 与管道抢同一个 stdin，read 会读到脚本本身
#   ⛔ 与 systemd 版同时跑会双份订阅/双份落库 —— 应急跑完记得 systemctl start ecas-monitor.service 收回去
```

> **认证已开时「没有数据」的两个常见原因**：① DTU 侧口令没同步（重填后必须同步，见注意事项 10）② 监视脚本漏了凭据（看日志「数据来源」行是「用户 ecas」还是「（匿名）」）。

## 四、⚠️ 注意事项

1. **本机 mosquitto 已开启认证**：`/etc/mosquitto/mosquitto.conf` 第 908 行 `allow_anonymous false`、第 912 行 `password_file /etc/mosquitto/passwd`；匿名连不上是正常的。
2. **⛔ 不要在服务器上裸跑 `ps -ef` / `ps aux`，也不要枚举 `/proc/<pid>/cmdline` 参数**：监视脚本的子进程是 `mosquitto_sub ... -u ecas -P <明文口令>`，这两类命令都会把口令**打进输出**（本项目已经因为这个原因轮换过两轮口令）。
   - ✅ 要看进程：`ps -o pid,stat,etime,comm`（只有程序名）或 `pgrep -x mosquitto_sub`（精确进程名，不带 `-a`）
   - ✅ 要确认「有没有带 `-P`」：只输出**计数**——`tr '\0' '\n' < /proc/<pid>/cmdline | grep -c '^-P$'`（结果 0/1），**绝不逐条打印参数**
   - 🎓 铁律：**任何可能出现在 `/proc/<pid>/cmdline` 里的秘密都等于公开**；凡是要「看」进程参数的地方，只允许布尔/计数结论，不允许回显内容
3. **`pkill -f <关键字>` 经 ssh 执行会杀掉自己**（远端 `bash -c` 命令行里含同一关键字），表现为 ssh 返回 255、后面的命令全不执行 —— 用 `kill <PID>`。
4. `1ms-helper` 在服务器上有 **3 份完全相同的副本**（`/root/tools/`、`/root/easytier/`、`/home/jc/`），sha256 均为 `34c70962ee17c707d66e500a17cd397879788648a374a7e7a125b992288ac60a`；只保留 `/root/tools/` 一份即可，其余可删。
5. **`watchtower` 容器处于崩溃重启循环**：
   ```
   Error response from daemon: client version 1.25 is too old.
   Minimum supported API version is 1.40, please upgrade your client to a newer version
   ```
   镜像太旧、与本机 Docker API 不兼容 —— 需换新版 `containrrr/watchtower` 镜像，或把 compose 里 watchtower 那段删掉（EasyTier 本身不依赖它）。
6. 磁盘：`/` 40 GB，已用 18 GB（44%）；Docker 镜像 164.6 MB，可回收 76.1 MB。备份目录按 30 天轮转，实测单份 dump 约 3.4 KB，无压力。
7. **数据库只监听 `127.0.0.1:5432`**（`listen_addresses = 'localhost'`，`pg_hba.conf` 用 `scram-sha-256`）—— 不要为了「远程连库」把它改成 `0.0.0.0`；跨机访问请走 SSH 隧道：`ssh -L 5432:127.0.0.1:5432 ecas`。
8. ⭐ **库里不存换算结果**（09-26 先生定案）：只有 `raw_reading(model, ts, raw)` 三列。`device` 表与 `v_reading` 视图**已删**，量程/补偿/阈值改为后端参数——改补偿值**只需改后端一处，历史数据完全不动**。旧数据（含 payload）已归档 `archive/raw_reading_v1-含payload-20260926-000500.sql.gz`。
9. `dpro66_readings.csv` **09-26 起换了列头**：新表头 `时间,raw,mA,浓度,未补偿,状态,原始payload`（旧表头第 5 列是 `浓度_x1.005`）。旧文件已归档为 `dpro66_readings.旧列头-20260925-235847.csv`，其数据已回灌入库。
10. ⭐ **常驻方式已从 `nohup` 改为 systemd**（09-26）：四个单元 `ecas-monitor` / `ecas-api` / `ecas-pgdump.timer` / `ecas-healthcheck.timer`。机器重启后自动恢复；`nohup` 起的进程**重启就没了**，不要再混用。
    - MQTT 口令以 **systemd 加密凭据**存放（`/root/ecas/credentials/mqtt-pass.cred`，`--with-key=host`），**服务器上没有任何明文口令文件**
    - 手动解密密文校验时要带名字：`systemd-creds decrypt --name=mqtt-pass /root/ecas/credentials/mqtt-pass.cred -`（否则报 `Embedded credential name … does not match filename …`）
    - 本机没有 TPM，只能用 `--with-key=host`；首次会打印 `Credential secret file '/var/lib/systemd/credential.secret' is not located on encrypted media, using anyway.`（提示，非错误）
11. ⛔ **恢复演练必须绕开两个权限坑**（已在 `ecas_pgdump.sh` 内置）：
    - `/root` 是 700 ⇒ `su - postgres -c 'pg_restore … /root/…'` 报 `could not open input file … Permission denied`。做法：用 postgres **建临时库**（`createdb -O ecas <临时库>`），**恢复与查数用 `ecas` 角色走 `127.0.0.1`**（root + `/root/.pgpass`）。
    - `/root/.pgpass` 的库名字段必须是 `*`（`127.0.0.1:5432:*:ecas`）；写死 `ecas` 时临时库匹配不上 ⇒ `fe_sendauth: no password supplied`。
    - systemd 环境不保证 `HOME=/root` ⇒ 脚本与单元都显式 `PGPASSFILE=/root/.pgpass`。
12. ⭐ **看门狗只在状态变化时写日志**：`health.log` 是空的**才正常**。有行就说明那一刻「数据断流 / 进程掉了 / DTU 被拒」状态变了，照行里的提示查。判据：**「断流 + DTU 被拒」= DTU 侧口令没同步**；「断流 + 没被拒」才轮到查 4G / 卡 / 服务器。
13. **日志轮转**用 `/etc/logrotate.d/ecas`（weekly × 8 + `copytruncate`）。必须 `copytruncate`：监视脚本以 `>>` 一直持有句柄，默认 `create` 方式会让它继续写老 inode、看起来「日志消失」。
