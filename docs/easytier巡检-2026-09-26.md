## 五、✅ 已决策：删安全组 `12121`（容器与绑定一律不动）

先生 2026-09-26 裁定：**按建议①处理 —— 在腾讯云安全组里删掉 `12121` 那一条，容器与监听地址不动**，浏览器管理改走 SSH 隧道。

> ⚠️ **删的时候只能删 `12121` 这一项**：控制台里 `11010 / 12121 / 21212` 很可能是**同一行**放行；`21212/UDP`（配置下发）、`11010 TCP+UDP`、`11011` 必须保留 —— 整条删掉才会真的断组网。

### 5.1 暴露证据

- 实测（2026-09-26，从外网云侧抓取）：`http://124.222.122.146:12121/` 返回 **EasyTier Dashboard** 的 `Login` / `Register` 页面 ⇒ **管理界面在公网上**。
- 账号面核查（只读）：`users` 表只有 2 行 —— `user`(id 1)、`admin`(id 2)，**没有任何陌生注册**；两个 hash 都不是上游默认 fixture 的原值（admin 已是 `$argon2id$…m=19456…`）。**但**「hash 不同」不等于「口令不是默认值」（同口令换盐也会不同），要 100% 确认请先生自己登一次或直接改掉。
- `user_running_network_configs` 里 admin 名下 1 条托管配置（1678 字符），字段含 **`network_secret`** ⇒ 该记录若泄漏，等同**可入网凭据**。
- 风险链条：控制台公网可达 ＋ v2.6.4 未修 #2445（任意已登录用户可读全部会话）⇒ 只要有人拿到一个登录态（含自助注册），就可能读到 `network_secret`。
- 备选②（未采用）：保留公网，但立刻改强 `user`/`admin` 口令并确认注册入口是否需要邀请码。
- 另注：`21212/udp`（config-server）按设计需公网可达，不动。

### 5.2 「关掉 12121 会不会让虚拟局域网崩？」—— 不会，三条证据

| 端口（进程） | 作用 | 关 `12121` 的影响 |
|---|---|---|
| `12121` TCP（`easytier-web-em`） | **只有 web 控制台 + REST API**（人机界面） | ← 就是它 |
| `21212` **UDP**（同一进程，fd 相邻） | **配置下发**：节点用 `--config-server udp://124.222.122.146:21212/admin` 取配置 | 不动 |
| `11010` TCP+UDP、`11011` UDP、`15888` TCP(RPC)、`41425` TCP、`32949`/`36779` UDP、IPv6 `11010/11011` | `easytier-core` 的 P2P / 中继 / RPC | 不动 |

1. **实盘**：`easytier-cli peer/route` 显示 mesh 里 **5 个节点**（`tencent-vm` = 本机 `10.10.10.123`，加 `DESKTOP-12PNJE0`、`oppc.local`、`CWKY-SXT`、`oranpear`），**全部 `p2p` DIRECT（tcp,udp）** —— 没有一条流量经过 12121。
2. **一次性容器实测**（`docker run --rm --network host --entrypoint easytier-web-embed …`，不动运行中的服务）：加 `--api-server-addr 127.0.0.1 --web-server-addr 127.0.0.1` 后 →
   `tcp LISTEN 127.0.0.1:18021`（api/web 收进回环）、**`udp UNCONN 0.0.0.0:18022`（config-server 仍全网可达）**。
   ⇒ 该工具**没有** `--config-server-addr` 选项，配置口固定绑 `0.0.0.0`；连容器侧收敛都不会碰配置面。
3. **结构上**：`12121` 属 `easytier-web`；节点组网只依赖 `easytier-core` 的 11010/11011 与取配置时的 21212。

### 5.3 关闭前必须先看的两件事（09-26 实测）

- ⚠️ `12121` 上当时挂着 **14 条外部连接**：`218.88.248.132`(7 条)、`36.170.12.194`(6 条)、**`45.33.12.122`(1 条，Linode 美区云主机 ⇒ 扫描/探测，与 MQTT 日志里那台 Linode 扫描器同类)**。前两个国内 IP 大概率是先生/同事浏览器开着的看板 ⇒ 关掉后那边会连不上，须改走隧道或另行放行。
- 隧道用法：`ssh -L 12121:127.0.0.1:12121 ecas` → 浏览器开 `http://127.0.0.1:12121/`；⚠️ 登录页的 **API Host 要填 `127.0.0.1:12121`**（否则前端仍去连公网 IP，关掉后打不开）。

## 六、升级时要注意的两件事

1. **数据在容器里，而且主要在 WAL 里**：`/app/et.db`（含用户与托管配置）**没有挂到宿主**（`easytier-web` 无任何挂载）⇒ `docker compose up -d` 重建容器会**丢掉账号与托管配置**。
   - ⚠️ **坑（09-26 实测）**：`/app/et.db` 本体只有 **4096 B**，真正的数据全在 **`et.db-wal`（696 312 B）** ⇒ **单独 `docker cp` 出 `et.db` 只会得到一个空库**（`sqlite3.OperationalError: no such table: users`）。
   - 正确做法：`docker stop easytier-web`（干净关停会让 WAL checkpoint 回主库）**或者**把 `et.db` 与 `et.db-wal`（+`et.db-shm`）一起拷出来再读。
   - 09-26 已按此法备好一份：`/root/ET/et-web-db/{et.db,et.db-wal,et.db-shm}`，校验可读 —— `users` = `admin`(id 2)、`user`(id 1)，托管配置 1 条。
   - 想彻底避免：给该服务加卷挂载 `- /root/ET/et-web-db:/app/db` 并把 `-d` 指向 `/app/db/et.db`（属配置变更，需先生确认）。
2. **升级会瞬断组网**：`up -d` 重建容器，几秒内断流，请在无人依赖组网的时段做；配置在 `/etc/easytier`，**不会丢**。
