# ECAS 采集端对接说明（DTU / 采集程序 → 后端）

> 适用对象：塔石 TAS-KS-301 DTU（现用），或任何替代它的采集程序 / 网关 / 边缘盒子。
> 目标：采集端只要满足本文约定，**后端一行代码都不用改**（`/root/ecas/` 下全部现成）。
> 相关：SOP `§八·B`（账号与主题命名）、`§八·C`（数据库）、`§八·D`（常驻运维与接口）。

---

## 一、采集端要做的三件事

1. 从 485 总线**轮询**仪表（Modbus RTU，主站）
2. 把**寄存器原始值**通过 MQTT **发布**到固定主题
3. **什么都不换算** —— mA、浓度、补偿、判断全部在后端算

```
浓度计 ──4~20mA──▶ 中盛 18 路 AI 模块 ──RS485 Modbus RTU──▶ 采集端(DTU) ──MQTT──▶ Mosquitto ──▶ 监视脚本 ──▶ PostgreSQL
                                                                                  (只收原始值)          (换算在后端)
```

## 二、MQTT 侧约定（硬性）

| 项 | 值 | 备注 |
|---|---|---|
| Broker | `124.222.122.146:1883` | 明文 1883（DTU 不支持 TLS）；8883 未开 |
| 用户名 | `ecas` | 全设备共用一套 |
| 口令 | **现读** `/Volumes/keys/ecas/mqtt.toml` | 指纹 `sha256[:12] = 96998b77dcff`；⚠️ 轮换后 DTU 侧必须同步 |
| ClientId | **每台必须不同** | 现用 `dpro66-01`；第二台 `dpro66-02`。**同 ClientId 会把前一个顶下线** |
| 数据主题 | `dpro66` | `<型号小写>[-序号]`；⛔ 不是 `ecas/dpro66/data`（已停用） |
| 命令主题 | `dpro66/cmd` | 预留（下发给现场），现未使用 |
| QoS | **1** | QoS 0 静默丢数；QoS 2 DTU 一般不实现 |
| Retain | **⛔ 绝对不要 retain** | retain 的消息会在**监视脚本一订阅的瞬间**被投递一次 ⇒ 库里凭空多一条旧值 |
| Keepalive | 60~120 s | 现用 60 s |

**认证已开启**（`allow_anonymous false`）：匿名连接一律被拒，日志里是
`Client dpro66-01 disconnected, not authorised.` —— 看到它 = **口令/用户名没对上**，不是网络问题。

## 三、Payload 约定（`dpro66` 主题）

### 1. 数据帧 = 11 字节，**Modbus TCP 格式**（不是 RTU，**没有 CRC**）

```
偏移  字节数  内容        值（本现场）
0     2      TID         00 00
2     2      PID         00 00
4     2      LEN         00 05      ← 后面还有 5 字节
6     1      从站地址     01
7     1      功能码       04         ← 读输入寄存器
8     1      字节数       02
9     2      寄存器值     30 39      ← ⭐ 大端（高字节在前）
```

- 例：`0000000000050104023039` ⇒ raw = `0x3039` = **12345**
- 寄存器值 = **mA × 1000**（即中盛模块给的原始整数）。**不做任何换算再发**
- 通道 1 = 输入寄存器 **0000H**（该模块 18 路地址连续：CH1=0000H … CH18=0011H）
- ⚠️ **不是** RTU 帧：⛔ 不要带 CRC（`01 04 02 xx xx CRC16` 那种是 RTU）；本现场 DTU 配的是「数据转换 → Modbus TCP」

### 2. 其它会被后端**忽略**的包

| 包 | 长度 | 处理 |
|---|---|---|
| 注册包 / 设备 ID | 16 字节 | 计入「其它」计数，不入库 |
| 心跳 | 可打印 ASCII 文本（通常每 120 s） | 同上 |

> 心跳在、但一直没有数据帧 ⇒ **采集端没从 485 拿到数据**（看 DTU 的 TX/RX 灯是否闪、轮询指令对不对）。

### 3. 时间戳：**没有**

Payload 里**不含时间**，库里 `ts` 是**服务器收到的那一刻**（`now()`）。
⇒ 已知限制：断网补发/离线缓存重放的数据，时间会是「补发时刻」而不是「采样时刻」。
若将来必须区分，做法是 payload 加时间字段（需同时改后端解析），或采集端本地落库补传。

## 四、采集端参数（塔石 TAS-KS-301 参考值）

| 项 | 值 |
|---|---|
| 485 参数 | **9600 / 8 / 1 / 无校验**（必须与中盛模块逐项一致） |
| 工作模式 | **Modbus 轮询（主站）**；⛔ 不是透传 |
| 从站地址 | `01` |
| 轮询指令 | `01 04 00 00 00 01`（RTU 需自算 CRC：`010400000001 31CA`） |
| 轮询周期 | 现用约 **100 s**；建议改 **5~10 s**（数据价值与流量权衡） |
| 上报方式 | 收到应答就 publish（QoS 1） |
| ⛔ 双主站 | **PC 上的中盛调试软件与 DTU 都是主站**，同时接总线会撞帧 ⇒ 调试时拔掉 DTU，或拔掉 USB-485 |

## 五、验收（部署完按顺序跑，全绿才算通）

```bash
# ① 认证体检：四组对照应「匿名被拒 / 正确口令通过」
/root/ecas/scripts/test_mqtt_auth.sh

# ② 后端全链路自检：发一帧假数据，看它落进 CSV + 日志 + 数据库，然后自动删掉
read -r -s -p 'MQTT 口令: ' P; echo; printf '%s\n' "$P" | /root/ecas/scripts/test_db_insert.sh
#   退出码 0 = 通过

# ③ 采集端真上线后：库里有没有新数据 + 接口怎么看
psql -X -qtAw -h 127.0.0.1 -U ecas -d ecas -c "SELECT count(*)||' 行，最新 '||coalesce(max(ts)::text,'-') FROM raw_reading;"
curl -s http://127.0.0.1:8080/api/health
/root/ecas/scripts/ecas_healthcheck.sh && tail -n 3 /root/ecas/logs/health.log
```

**判据表**

| 现象 | 结论 |
|---|---|
| `not authorised` 反复出现 | 采集端口令/用户名不对（用指纹比对现役口令） |
| 认证 OK、心跳有、无数据帧 | 采集端没拿到 485 数据（轮询指令 / 接线 / 双主站冲突） |
| 有数据帧但值恒为 0 | 从站地址或寄存器地址错（如读到了没接线的通道） |
| 值 ≈ 13332 而现场约 12935 | 字节序颠倒（低字节在前） |
| 库里时间正常但值离谱（>20500 或 <3600） | 量程/回路问题：<3600 按断线报，>20500 标不可信 |

## 六、如果用**别的采集程序**（不用塔石 DTU）

两条路，任选：

**A. 照上面的 MQTT 约定发**（推荐，后端零改动）
任意语言（Python `paho-mqtt` / Node `mqtt.js` / C 网关）发布 11 字节帧即可，后端解析器认的就是它。

**B. 直接写库**（采集端与库同机、或愿意配 `.pgpass` 时）
```sql
INSERT INTO raw_reading (model, ts, raw) VALUES ($1, now(), $2) ON CONFLICT DO NOTHING;
```
- ⛔ 只写 `model / ts / raw` 三列，**不要**在库里算浓度、不要加列
- 主键 `(model, ts, raw)` 天然去重：重放同一帧不会产生重复行
- 口令走 `/root/.pgpass`（600，**库名字段是 `*`**），⛔ 不进命令行、不进环境变量文件

**C. 发别的格式（JSON 等）** —— 需要改后端解析器
改动点只有一个文件：`/root/ecas/scripts/dpro66_monitor.sh` 的 `handle_line()` / `decode_hex()`。
⛔ 动之前先抓一次真实 payload 存证（`mosquitto_sub -h 127.0.0.1 -t dpro66 -F '%I|%x'`），**别照猜写解析**。
